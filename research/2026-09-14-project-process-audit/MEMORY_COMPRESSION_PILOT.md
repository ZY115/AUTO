# 最小设计：记录经历与归纳任务状态的差异

状态：设计完成；仅进行了排列枚举验收，未运行 RL。目的不是证明自动机优于一切程序，而是检验：把完整历史用作状态，与把未来等价历史合并用作状态，是否造成学习差异。

**2026-09-15 解释边界补充：这是记忆机制诊断，不是完整的长程探索实验。** 检查顺序由环境给出，前面只有一个合法动作，最后才作一次选择；实质上是一个以事件历史为输入的二选一决策学习任务。由于终局反馈确定且恰有两个动作，每幕无论选哪个动作，都能恢复该历史的正确答案，因此它不检验主动探索如何改变信息采集。第二层只检验逐幕更新的部分规则何时用于决策；不能据此宣称验证了前沿探索、导航技能复用或一般在线自动机归纳。Direct-rule 很可能已足以解决这种小任务，必须保留，不能将其成功解释为设计失败后再人为削弱。

## 1. 为什么要从这样一个小任务开始

Stage 8 已经做过“敏感事件对的先后顺序决定后缀”的压缩实验。正确紧凑状态相对完整历史有局部收益，但真实状态是特权参照，复杂地图、合并算法和附加机制使解释变长。本设计是该机制的精简诊断，不是新任务思想或新方法的声明。

本轮单独回答“历史压缩如何改变记忆和经验共享”。原始的“未知任务中在线发现并立即利用”作为同一任务的第二层比较；第一层通过不自动证明第二层。

## 2. 任务：同一工作台，检查记录决定最终操作

一幕有 n 个不同检查事件，初版 n=3，标签 A、B、C。系统将它们按随机顺序送到工作台。智能体每执行一次检查动作，获得该物体标签和检查完成反馈。检查完毕，再执行一次固定的“到决策点”动作，进入相同的决策观测；最后在 X、Y 两种操作中选一个。

隐藏任务规则：若 A 比 B 先检查，最后应选 X；否则应选 Y。C 不影响最终要求。正式未知规则条件会随机选择敏感事件对及 X/Y 的对应方向，不把 A/B 固定为算法内置特征。

X/Y 选择正确终局奖励 1，否则奖励 0，均结束本幕。前面检查无奖励。事件标签、检查反馈和终局反馈对所有方法相同。没有塑形、技能库、经验回放或步进惩罚。

所有方法执行相同的真实检查过程，不免费传送到决策点。固定汇合动作也计入环境预算；每幕训练成本 n+2 步。这里的随机供件顺序是环境输入，不是专家演示。它让智能体必须处理多种历史，避免它总选择同一条顺序而绕开记忆需求。此版本不研究导航策略或搬运技能。

决策时物理观测完全相同：物体已处理完、当前位置相同、进度相同、最后可见事件也是相同汇合标记。不能在观测中保留已经排序的物体列表或隐藏的正确答案。

| 历史（省略共同汇合事件） | 正确操作 | 最终任务状态 |
|---|---|---|
| A B C | X | A 先于 B |
| A C B | X | A 先于 B |
| C A B | X | A 先于 B |
| B A C | Y | B 先于 A |
| B C A | Y | B 先于 A |
| C B A | Y | B 先于 A |

两类历史对于剩余可行动作的奖励与终止完全相同，因此这里的合并是精确的未来等价，不是仅凭看见一次相同下一目标作猜测。

## 3. 四个参照，分别说明什么

| 臂 | 最终决策表的键 | 用途 |
|---|---|---|
| Count | 已检查次数 | 信息不足的诊断臂，不是主要对手 |
| History | 完整有序事件历史 | 主要的“如实记录任务经历”基线，信息充分 |
| Compact-oracle | 真正敏感事件对的先后关系 | 正确压缩的特权参照，不算学习方法 |
| Handwritten-oracle | 手写先后标记，语义与 Compact-oracle 相同 | 等价实现验收，应与自动机逐位相同 |

四臂使用相同 tabular Q-learning、相同 epsilon、alpha、初始化、终局奖励和更新次数。检查阶段只有一个合法动作，最终阶段两个动作。已知压缩只提供任务状态的划分，不额外通过接口路由到 X/Y；因此第一层量的是表示变化带来的经验共享，而非提供正确动作的收益。但划分本身来自真规则，仍然是特权信息，必须标注。

在全排列均匀评价、冻结策略且禁止评估时更新/保留额外历史的条件下，Count 的最大期望成功率是 50%。History 可以表示正确决策，失败不能归于表达能力。Compact-oracle 与手写等价标记应完全一致；不一致先查实现，不解释成自动机优势。

## 4. 压缩机会的精确验收

枚举所有排列，按“敏感对谁先”分组：

| 检查事件数 n | 完整历史在最终决策处的状态数 | 正确压缩在最终决策处的状态数 |
|---|---:|---:|
| 3 | 6 | 2 |
| 4 | 24 | 2 |
| 5 | 120 | 2 |

这张表已通过排列枚举确认。数字只针对最终决策处，不是整台自动机的总状态数，也不是已测学习加速倍数。任务输入长度随 n 增长，所以同时报告幕数和全部环境步；各 n 内方法成本配对。不要沿用静态单点地图能强制 n! 最优顺序的错误假设：本任务的全排列来自明确的随机供件机制。

第一轮只做 n=3、4，不立即扩到更大任务。

## 5. 未知规则版本：学习压缩也要付成本

为使第二层真正可行，先限定一个小而明确的任务族：已知最终操作由某一对检查事件的先后决定，但不知道是哪一对，也不知道先后对应 X 还是 Y。n=3 时有 6 个候选规则，n=4 时 12 个。所有可学习的规则臂都知道同一任务族先验。

每幕观察完整检查历史、自己的最终动作和二值反馈后，更新候选集合。因为终局只有 X/Y 两种操作，且反馈确定，成功或失败都能确定该条历史应对应哪种操作。若未来引入更多操作或反馈噪声，这个推断就不再原样成立。

第二层增加三种对照：

- **Learned-state-now**：在线维护一致候选规则。对当前候选，给历史构造“各候选会给出什么最终判断”的向量；向量相同的历史才共享决策状态。候选减少时重新编码旧经历。此为族先验下的任务状态学习，不称一般 DFA 学习。
- **Learned-state-delayed**：运行同样的候选更新，但在只剩一个候选规则之前仍按完整历史决策；之后才使用相同压缩。
- **Direct-rule**：用同一候选集合直接投票选 X/Y，无需 Q-learning。它是必须保留的强对照，用于检查在这个简单任务里是否连 RL 都没有额外作用；候选分歧时用预先冻结的同一选择规则。

第一层先验证表示效应；第二层再量候选识别成本、何时可共享、是否必须等完整规则明确。不要把两层的不同信息条件混成一个方法排名。

结构修订时只重放真实存档经历，History 对照获得等量更新；环境交互数、TD 更新数、候选检验次数分别记账。候选遍历成本不伪装成零。所有结果包含从第一幕起的学习成本，不以归纳完成时刻重新计时。上述向量键只是受限任务族的一种可执行归纳方案，不主张它新颖或必然优于 Direct-rule。

## 6. 最小执行与结束条件

1. 先做语义与信息泄漏验收：同物理观测的两类历史需要不同操作；历史足够；oracle 合并无冲突；手写/自动机等价；候选集合始终包含真规则。
2. 第一层 n=3、4，30 个配对训练种子，每次 2,000 幕，所有方法完整跑到预定终点。用均匀全排列精确冻结评价，每 10 幕记录成功率。此预算是小实验设计值，不保证一定处于最佳测量区间；若首轮显示无法分辨，如实记录后再制定下一版，不按结果好坏延长某个臂。
3. 主结果是固定预算内的成功率曲线、环境步加权 AUC、最终成功率；首次 90% 作为带评估分辨率和删失标记的辅助量。完整保留每个种子的曲线。
4. 第一层回答清楚后，才执行第二层。对 n=3 的 6 个隐藏规则全部测试，n=4 的 12 个全部测试；先按规则成组，不把所有种子当作独立规则。无需立即做地图或机器人扩展。

读判：

- Oracle 比 History 快：支持当前学习器在该任务族中从正确的历史压缩获益，不证明已经能低成本学到压缩。
- Learned-state-now 加上识别与修订成本仍比 History 好：支持可学习的任务状态抽象有收益。
- Now 比 Delayed 好：支持部分结构应立即使用。
- Direct-rule 持平或更好：承认简单规则学习已足够，自动机/RL 组合没有额外优势；保留其作为有效实现，不为制造优势削弱它。
- Compact-oracle 与 Handwritten-oracle 相同：预期结果，说明收益来自相同的任务抽象，不来自自动机的名字。

本任务的目标是把概念测清楚。即便有正结果，也不直接声称真实机器人、任意历史记忆或一般自动机学习上的优势。
