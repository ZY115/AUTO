# Decisions and evidence

## Before first run

Use a progress-counter baseline because reliable step feedback reveals the stage in a linear chain. Do not require an oracle-state advantage as a go/no-go condition: oracle state and counter carry the same information here. Instead, distinguish knowing the state from knowing the future transition labels, which can enable counterfactual experience reuse. Start on a benign grid to establish the null/positive mechanisms before introducing failure structures.

## Literature boundary (primary publication pages checked 2026-09-09 local time)

* Xu et al., ICAPS 2020, [Joint Inference of Reward Machines and Policies](https://ojs.aaai.org/index.php/ICAPS/article/view/6756): already iterates hypothesis RM learning and Q-learning, using inconsistent trajectories and transferring Q-functions. Therefore online joint learning alone is not a novelty claim.
* Koprulu and Topcu, UAI 2023, [Reward-machine-guided, self-paced reinforcement learning](https://proceedings.mlr.press/v216/koprulu23a.html): uses RM structure in policy/value updates and curriculum distributions.
* Wang et al., L4DC 2025, [Mission-driven Exploration](https://proceedings.mlr.press/v283/wang25d.html): uses a task automaton and a partial interaction model to guide exploration.

This is a mechanism pilot and a limited literature check, not a systematic novelty assessment or reproduction of these algorithms.

## Stage 1 observation → Stage 2 design

288 runs (8 seeds, four task lengths, nine methods) finished. All count-based methods eventually solve; flat solves none. At k=8, mean first90 checkpoint is 20,000 for count and progressive, 10,625 for learned_qrm and progressive_qrm, and 6,250 for oracle_qrm. The 5k checkpoint resolution is too coarse near 5–20k learning times. Count/discovered/oracle_state and progressive/count_frontier have exact matched Q/trace hashes, checked separately.

Stage 2 retains the existing implementation and varies epsilon for BOTH ordinary count and learned_qrm (.05,.2,.5); tests progressive high=.2,.5,.8 at low=.02, plus high=.5/low=0 and high=.5/master_n=1. This asks whether gating helps beyond tuning ordinary epsilon. Use k=4,8, seeds 0..11, budget60k, checkpoint1k, benign H=24k, tight H=12k, and noisy H=12k/slip=.15. The minimum possible path depends on the task: a separate shortest-path feasibility audit will accompany tight-horizon interpretation. These are development data; new seeds will be reserved for confirmation.

## Stage 2 observation → Stage 3 design

1224 sensitivity runs finished. In benign k=8, count epsilon=.05 costs 15,750 steps versus progressive high=.2 at 15,583, a negligible development-set difference; learned_qrm epsilon=.05 costs 7,333. Under tight k=8, reducing ordinary epsilon from .2 to .05 lowers capped cost from 27,750 to 20,250, close to progressive high=.2 at 19,750. Thus a large improvement over untuned epsilon=.2 would overstate the frontier contribution. In noisy-tight k=8, learned_qrm costs 29,833 vs count 33,250, with both 9/12 first90 hits and some later performance loss. More aggressive frontier exploration usually hurts.

Stage 3 asks if the useful signal is **reusable local navigation skills**, rather than exploration gating. Add: (1) option_count terminates Bellman bootstrap at each progress event, isolating local subtask learning; (2) option_qrm adds known-edge counterfactual updates; (3) goal_reuse learns one reaching policy per observable label from every physical transition and uses that policy after the corresponding task edge is discovered; (4) count_replay and option_replay perform eight extra uniform buffer updates per physical step, matching goal_reuse's nine total updates. This is standard goal-conditioned relabeling/skill reuse with a discovered sequence list, not a novel automaton inference algorithm. No future target order is revealed. Because dynamics do not depend on task stage, relabeling is valid in this environment; it would not automatically be valid for manipulation with task-dependent object state.

Goal-policy reward is +1 on entering that label, step cost -.01, zero bootstrap on reaching it. Other events and actual task/episode endings do not terminate the hypothetical local skill. Every task interaction still obeys the original reward and reset. Goal learning uses all eight labels from the outset, so information and update advantages are explicitly reported. The task-Q learner remains available for unknown stages. Compare global epsilon=.05 and a progressive goal variant; include oracle_goal with target sequence known before training. Evaluate alpha=.1 as a noise-stability check. Use the same development seeds, conditions, budget and checkpoint frequency as Stage 2. Independent held-out confirmation follows only after selection is frozen.

## Stage 3 observation → Stage 4 calibration

1224 runs completed. Benign k=8: goal_reuse costs 4,583 steps, count_replay with the SAME nine updates per interaction costs 5,167, compared with count 15,750. Thus most of the original apparent structural benefit can also come from ordinary extra computation. In noisy-tight k=8, first90 costs are nearly tied (goal 23,167, replay 23,333), while AUC differs (.710 vs .591); a first-hit metric alone misses learning stability. Decreasing alpha to .1 slows early learning and can improve final stability for replay, but does not dominate.

Independent optimal finite-horizon DP found 5 of 72 development task/condition instances cannot attain 90% even with privileged optimal control. Their raw data remain intact; they must not be described as algorithmic failures. Subsequent confirmation conditions will be audited before interpretation, and report feasibility explicitly.

Stage 4 checks a missing strong control: zero/very-low epsilon. Zero-initialized Q is already optimistic with a negative step cost, so deterministic exploration may not require sustained epsilon at all. Compare count, learned_qrm, count_replay and goal_reuse at epsilon 0,.005,.02,.05; progressive and progressive_goal at high=.05 or .2, low=0; oracle_goal epsilon=.02. Use 12 development seeds and k=4,8 in benign H=24k, noiseless deadline H=16k and noisy H=20k/slip=.2. Budget40k, checkpoints500. Select one fixed configuration per method using pooled normalized AUC over all development conditions/lengths, before evaluating held-out seeds100..131. The parameter search is balanced for the strongest non-progressive baselines; new conditions are intentionally less dominated by physically impossible 90% thresholds.

## Stage 4 observation → frozen held-out Stage 5

1512 calibration runs completed. Pooled development AUC selects count epsilon=.02 (.6812), learned_qrm epsilon=.02 (.8376), count_replay epsilon=.05 (.8851), goal_reuse epsilon=.005 (.9018), progressive high=.05/low=0 (.6812), progressive_goal high=.05/low=0 (.9025). The difference between the two goal variants is tiny on development data. Pure greedy is not universally superior; zero initialization provides optimism but does not remove all exploration/local-trap issues, especially with replay. Keep all raw calibration outcomes.

Freeze these configurations (alpha=.3, gamma=.98, mastery5/.8) for 32 held-out seeds100..131, lengths2,4,6,8,12,16, conditions benign H=24k/slip0, deadline H=16k/slip0, noisy H=20k/slip.2. Budget100k, evaluation interval1k. Oracle_goal and oracle_qrm use epsilon=.02 as privileged references; no assertion that either is a strict upper bound. No further hyperparameter selection on this test set. Primary comparisons: progressive vs count; learned_qrm vs count; goal_reuse vs compute-matched count_replay; progressive_goal vs goal_reuse. Paired bootstrap resamples seeds within each length/condition. Inspect AUC and final success alongside censored first90 cost. Audit optimal feasibility for every held-out instance and preserve impossible instances explicitly rather than silently deleting them.

## Held-out observation → Stage 6 causal follow-up on another seed set

The 4608 held-out runs completed. At benign k=16, tuned count costs33,781, progressive33,438, compute-matched replay11,781, goal_reuse6,062. At noisy k=16, count50,094, progressive59,906, replay17,812, goal_reuse7,406. Thus skill reuse survives the compute control and the frontier schedule is not the main gain. These results are not used to change the frozen method hyperparameters.

One remaining causal ambiguity: does the gain require **immediate use of partially discovered structure**, or just having a goal-policy bank? Stage 6 uses entirely new seeds200..231, k4,8,16, the same three audited condition definitions, budget100k, checkpoint1k. Compare goal_reuse (unchanged epsilon=.005) with delayed_goal, which trains exactly the same eight auxiliary goal tables from the beginning but may use them only after observing the first complete task success. Both do nine updates per interaction; only the time at which partial knowledge influences behavior changes. Add known_goal, which trains auxiliary skills only for labels already identified in the task prefix, to quantify the benefit of training observable-but-not-yet-task-confirmed goals; it does fewer updates and is not a compute-matched causal test. Include count_replay epsilon=.05 as the strong control. Report first complete training success and prefix/frontier step accounting, in addition to fixed-policy evaluation. No hyperparameter tuning occurs on these new seeds.

## Stage 6 outcome and stopping decision

All1152 follow-up runs completed. At k16 with action noise, immediate use costs6906 steps versus delayed use37938, with identical nine updates per interaction; the paired cost ratio is.182, 95% interval [.170,.194]. Before first complete training success, known-prefix execution falls from33194 to2566 steps while unknown-frontier interaction is roughly4218 versus3741. Known-goal-only training still costs9719 versus ordinary replay18594. These data isolate immediate reuse more directly than an epsilon ablation.

The pilot now has enough evidence for a research decision: retain immediate use of partial task knowledge and reusable skills; do not present epsilon frontier scheduling, TL syntax, or general automaton induction as the supported contribution. Short tasks are an explicit negative condition: ordinary replay wins at k2–4 in deterministic settings. The next scientific phase should introduce ambiguous/branching task histories and structure uncertainty, with appropriate inference baselines; it should not simply scale this open-grid setup to PPO or a robot.
