# Stage 8R：推断与塑形审计，两个结论反转

**第五步报告里的两条主要结论被推翻，原因是三个实现缺陷。** 修复之后：

- **H4 的 No-Go 撤回。** 修好的合并器相对完整历史是 **1.76 倍 [1.69, 1.83]**，把到真实最小自动机的差距补上了 75%。原报告说它"贡献恰好为零，比值 1.00"。
- **H5 里"学习版塑形比特权版差两倍"是尺度假象。** 统一尺度后两者比值 0.97 [0.94, 1.00]。而且拆开首次成功前后可以看到，真正的部分结构塑形在**第一次成功之前**就有 4.71 倍 [4.39, 5.05] 的作用。
- **L\* 式查询选择的零结论存活**，重跑后是 0.968 [0.943, 0.993]，略差而非略好。

## 1. 三个缺陷

**缺陷一，冲突检测只读并查集代表的证据。** 三节点反例：节点 A 对事件 0 没有任何证据，B 观察到它推进，C 观察到它被忽略。先合并 A 与 B，代表变成 A；再检查 A 与 C 时只读 A 自己的证据，B 的证据丢失，一对直接矛盾的节点被并进同一个类。已写成回归测试，并附一份旧规则的实现证明它确实通不过。

**缺陷二，配额只在顶层检查。** `rebuild` 只对候选对检查配额，`compatible` 传播出的后继对被无条件合并，子节点从不重新检查。

**缺陷三，`deepest` 从未被赋值。** 源码里只有声明和读取，中间那次补丁的目标字符串已被更早的补丁改掉，替换静默变成空操作。后果是首次成功之前势函数恒为零，所谓"学习到的势"实际上是一个事后校准的进度计数势。

**另外还有我自己的一处报告错误。** 第五步写的"合并精度 1.00"来自单种子单台阶探针，正式数据六个台阶分别是 0.555、1.000、1.000、0.310、0.606、0.725，平均 0.699。

## 2. 修法

合并改为**类级证据聚合加试探性合并**：并查集每个类携带成员证据的并集，任何检测只读类不读节点；合并先在带撤销日志的结构上计算整个闭包，闭包中任一对不通过就整体回滚，不留半成品。配额是否约束传播出的子节点做成开关，两种读法都测而不是假设。

塑形拆成四个命名版本，统一尺度：不塑形、计数势、frontier 势、oracle 势。计数势就是原代码实际做的事，把它命名出来是为了不让它被当成关于部分结构的证据。

## 4. Gate 2：真实训练证据下四种规则

均匀随机抽稀的证据会低估问题，因为真实缺失是系统性的：agent 不会回头去碰已经完成的标签。所以用真实训练里导出的证据重做，策略完全移除，四种规则读同一份数据。

不绕路，覆盖 0.54，48 次运行：

| 规则 | 精度 | 召回 | 类数/真实 |
| --- | --- | --- | --- |
| 旧规则 | 0.24 | 0.65 | 0.93 |
| 新，无配额 | 0.51 | 0.57 | 1.25 |
| 新，配额1 | 0.88 | 0.39 | 1.54 |
| 新，配额1 加严格子节点 | 1.00 | 0.00 | 2.96 |

**修复把精度从 0.24 提到 0.88。** 所以第五步的失败里，相当一部分是错误合并，而不是"正确合并太少"。

严格子节点检查的召回**恰好是 0**，它是"安全但完全不合并"。我重写时把它设成了默认，这是一个新引入的错误，已改回宽松传播。

## 5. H4 重测

开发集在 theta 取 20、50、100、200 与配额 1、2 上选出 theta=20、配额 1、宽松传播。正式确认换新种子 800 到 831。

| 臂 | 达标步数 | AUC | 最终成功率 | 合并精度 | 召回 | 类数/真实 |
| --- | --- | --- | --- | --- | --- | --- |
| 完整历史 | 31,599 | 0.892 | 1.00 | | | |
| 学习合并 | 17,932 | 0.930 | 1.00 | 0.93 | 0.44 | 1.54 |
| 真实最小自动机 | 13,318 | 0.948 | 1.00 | | | |
| 完整历史 加 frontier 塑形 | 5,474 | 0.987 | 1.00 | | | |
| 学习合并 加塑形 | 4,896 | 0.988 | 1.00 | 1.00 | 0.08 | 2.01 |
| 真实最小自动机 加塑形 | 3,016 | 0.994 | 1.00 | | | |

配对比较：学习合并相对完整历史 1.76 [1.69, 1.83]；距离真实最小自动机 1.35 [1.30, 1.39]。**H4 现在是 Go。**

一个值得记的相互作用：加上塑形之后学习合并的召回掉到 0.08，相对历史的优势缩到 1.12 [1.08, 1.16]。塑形让学习太快，合并器来不及积累证据。

## 6. H5 重测

统一尺度 0.05，在开发集上按三种塑形的合并 AUC 选出。正式确认换新种子 700 到 731。

| 塑形 | 达标步数 | 首次成功 | 首次成功之后 | AUC |
| --- | --- | --- | --- | --- |
| 无 | 32,073 | 6,496 | 25,577 | 0.891 |
| 计数势 | 11,641 | 6,496 | 5,144 | 0.956 |
| frontier 势 | 5,526 | 1,380 | 4,146 | 0.987 |
| oracle 势 | 5,698 | 1,303 | 4,395 | 0.986 |

**只看第一次成功之前**：计数势 1.00，区间退化成 [1.00, 1.00]，一点作用没有，首次成功时刻与不塑形完全相同；frontier 势 4.71 [4.39, 5.05]；oracle 势 4.99 [4.64, 5.33]。

frontier 势相对 oracle 势 0.97 [0.94, 1.00]。**只用已发现结构算出的势，与读真实距离的势基本相等。**

本族里每条被接受的历史长度相同，所以深度等于图距离，frontier 势不是一般图距离势的检验。

## 7. 哪些结论未受影响

压缩本身的价值、稀疏化改造、第三步那条仿射成本律、覆盖率饱和且加大 epsilon 无效、探索分解里"朝没拿过的标签走"值 1.63 倍这几条，都不经过合并器或塑形，全部不变。重跑后"试得最少相对朝没拿过的标签"是 1.320 [1.257, 1.385]，与原来的 1.28 一致。

## 8. 验证

25 项测试通过，在原 18 项之上新增 7 项：成员证据冲突必须阻止第二次合并；同一反例上旧规则必须失败，证明测试有杀伤力；传播出的子节点必须受配额约束，开关两种取值都断言；两层之下的矛盾必须导致整次合并作废；失败的尝试必须不留任何痕迹；顺序依赖性作为诊断记录而非硬指标，当前规则在该测例上产生两种划分；独立 Python 实现在三组真实转储上与 C++ 划分完全一致。
