# 跨地图任务自动机复用：文献与实验建议

检索日期：2026-09-10。基于论文原文、作者代码仓库与官方环境文档。此次确认了资料与仓库的可访问性，没有安装第三方依赖或验证其在本机上的运行兼容性。

## 方向判断

建议将“跨地图复用学习到的任务自动机”提升为下一阶段主线，把不可逆性放在随后的一组受控压力测试中。上一次提出的冻结势实验保留为诊断工具，不必先完成它才开展迁移实验。

前者直接检验最初的研究目标：从交互中提取与具体地图无关的任务知识。后者检验错误任务记忆的代价，但也会放大错误合并的损失，未必自动有利于学习自动机。二者适合递进组合。

实际应用例子是：同一巡检、取送或操作流程换到另一个建筑，业务规则保持，目标位置和路径重新学习。工程上手写任务机也能做到；研究问题在于这份规则能否从有限经验中可靠获得，并以低成本复用，而不是证明 TL 语法具有独有能力。

## 最相关的文献和工具

### 1. ISA：从交互轨迹学习子目标自动机

Furelos-Blanco 等，AAAI 2020；扩展论文 JAIR 2021，Induction and Exploitation of Subgoal Automata for Reinforcement Learning。

交替执行 RL 与自动机归纳，并将学到的结构用于 QRM 或分层 RL。成功、死路和未完成轨迹的区分尤其适合拟加入的不可逆实验。其多任务/多实例框架与本项目相关，但不能把所有相关实验都说成“源图上学好后仅迁移结构到全新图”的严格对照。

可借用：事件轨迹接口、接受/拒绝状态、反例驱动修订、QRM/HRL 结构利用接口。

依赖包含 ILASP、clingo 和旧版本环境栈。作为强文献基线值得看，当前小实验不必为了运行整套仓库重构已有 C++ 环境。

[论文](https://arxiv.org/abs/2009.03855) · [作者代码](https://github.com/ertsiger/induction-subgoal-automata-rl)

### 2. TALearner：源环境造成的结构偏差

Abate 等，Learning Task Automata for Reinforcement Learning Using Hidden Markov Models，ECAI 2023。

从学习到的环境与任务乘积中提取任务自动机，专门讨论环境偏差：一张地图强迫事件 A 出现在 B 前面时，仅凭这种经验不一定能判断 A 是否真是任务前提。论文说明不同任务自动机可能在同一环境中产生相同的乘积行为。

这直接提醒我们：源地图策略成功率高，不等于学到了能跨地图泛化的任务规则。当前项目还提供进度反馈，比纯奖励设置更强，不能照搬其不可辨识结论；但从未试过的事件/历史仍然可能无法区分。

可借用：源地图偏差对照、任务语言层面的验证、乘积模型与任务模型的分离。作者代码是 C++ 小网格基准，不是可直接替换当前学习器的通用接口。

[论文](https://arxiv.org/abs/2208.11838) · [作者代码](https://github.com/dkhyland/TALearner)

### 3. Reward Machines：把结构用于新地图上的学习

Toro Icarte 等，Reward Machines: Exploiting Reward Function Structure in Reinforcement Learning，JAIR 2022。

提供结构塑形、任务分解和反事实经验等方法。对本项目最有用的是乘积状态 Q(s,u) 与 CRM：在满足环境转移和事件标注可跨任务状态重用的条件下，一条实际交互能更新多个任务状态下的学习目标。

可借用：以结构扩展状态与重标注经验的基线，避免只能通过距离势检验自动机价值。必须计入全部更新开销。作者仓库仍说明依赖 Python 3.6/3.7、旧 Gym/Baselines 和 TensorFlow 1.x，宜借用核心逻辑与测试，不把整个旧栈作为新项目基础。

[论文](https://arxiv.org/abs/2010.03950) · [作者代码](https://github.com/RodrigoToroIcarte/reward_machines)

### 4. AALpy：最轻量的独立推断基线

Python 自动机学习库，支持 DFA、Mealy、Moore，以及主动学习和被动的 RPNI 等方法。对于已有事件/进度/终止日志，可以优先做 Mealy 输出序列的被动学习对照，而不用重新实现另一套合并器。

建议数据契约：输入为所有实际发生的标签事件，输出为推进/忽略/成功/失败等可观察反馈；明确空事件与重复事件的处理。被动学习只用共同日志。不能将超时简单标成任务永久失败，也不能把未知边默认为真实拒绝。

主动 L* 需要查询接口；本项目不能免费调用真实任务机回答任意事件串。物理执行的查询要计入交互预算，不可达查询应记为不可执行。由真实自动机回答的查询只能作为诊断参照。

[官方仓库与安装说明](https://github.com/DES-Lab/AALpy) · [Mealy/RPNI 示例](https://github.com/DES-Lab/AALpy/blob/master/Examples.py)

### 5. C-PREP：利用结构指导下一子目标的迁移基线

Contextual Pre-planning on Reward Machine Abstractions for Enhanced Transfer in Deep Reinforcement Learning。在上下文相关的奖励机上预规划，再把期望的下一抽象转移提供给学习器；实验包含实体位置与地图墙体变化。

可借用：源/目标环境划分和“给下一子目标”的结构接口。与本项目的差异是其方法使用上下文相关 RM，并不解决从当前有限源地图轨迹归纳未知任务机的问题；抽象图中的最优转移也未必是新地图环境步数最短的选择。

[论文](https://arxiv.org/abs/2307.05209) · [作者代码](https://github.com/CLAIR-LAB-TECHNION/C-PREP)

### 6. 不可逆实验的现成参照

MiniGrid Memory 让智能体记住起点物体，走过走廊，在分岔处选择匹配物体；到达错误物体也会结束回合。这是“历史决定正确选择、错选无法在本回合补救”的直接环境原型。

可借用任务机制；首轮仍放在当前表格环境里，避免同时引入朝向、局部图像观测和神经网络。若以后迁入 MiniGrid，应将感知问题与任务记忆问题分开。

[官方环境说明](https://minigrid.farama.org/environments/minigrid/MemoryEnv/)

Hierarchies of Reward Machines（ICML 2023）还提供开放地图、房间/熔岩和死路设置，以及任务结构归纳的基线。论文中的手写 HRM 策略比较不能误称作已完成了我们的纯结构迁移实验。

[论文](https://proceedings.mlr.press/v202/furelos-blanco23a.html) · [作者代码](https://github.com/ertsiger/hrm-learning)

若之后研究硬动作屏蔽，可参考 Safe Reinforcement Learning via Shielding；它需要相应的安全规格与模型条件，不能为一个可能错误的学习自动机自动提供安全保证。

[论文](https://cdn.aaai.org/ojs/11797/11797-13-15325-1-2-20201228.pdf) · [作者代码](https://github.com/safe-rl/safe-rl-shielding)

## 最小的跨地图实验

### 信息契约

- 源图 A 与目标图 B 的事件词汇、任务规则、进度/终止反馈语义保持一致；改变标签实例位置、连通关系和最优事件顺序。
- 只迁移事件级自动机及其声明过的置信/证据信息。重置任务 Q、技能 Q、地图边、位置计数、环境步数距离、物理轨迹缓冲区和位置相关势。
- 原始事件日志可以提供给专门的同信息基线，但其中不得携带地图位置和动作价值。
- 目标图的地图知识必须由目标交互获得；真实 B 地图与真实任务机的乘积仅用于评估，不用于学习臂控制。
- 当前进度反馈是额外任务信息，须对所有同等级基线一致提供；不能把这称为仅凭终端奖励恢复结构。

### 学习器的首轮使用方式

先用冻结任务机扩展新图上的 RL 状态 Q(s_B,u)，让全部物理价值从零学习。这已经是使用乘积状态，不要求先知道完整 B 地图。暂不把先前失败的动态乘积塑形加进来。

若这一步太弱，再统一加入结构子目标或 CRM，明确这是第二个机制轴，匹配所有更新预算。得到部分 B 地图后再研究显式乘积规划。

### 对照组

| 组 | 来源信息 | 目的 |
| --- | --- | --- |
| 目标图从头学习 | 无源任务知识 | 测总体复用收益 |
| 迁移源事件前缀/非合并模型 | 同一批源事件反馈 | 区分源经验收益与结构合并、泛化收益 |
| 迁移学习自动机 | 同一批源事件反馈 | 主方法；第一轮冻结，下一轮允许反例修订 |
| 真实自动机/等价手写监控器 | 真实任务规则 | 标明特权的结构参照与接口正确性检查 |

未知事件后继统一使用声明过的回退；不能让非合并基线遇到未知前缀立即失败，却允许主方法继续学习。若后续使用 CRM，两种模型应获得相同的重标注机会和总更新预算。

可另用 AALpy 对同一份源数据学习一张 Mealy 机，用作推断算法基线，不需在首个机制检查中一次加入所有外部方法。

### 地图与评估

建议起步为 2 个任务、每个 1 张源图与 3 张冻结的新图、8 个训练种子。这个规模用于机制检查；最终确认再增加独立源图和目标图，不能用更多训练种子替代地图多样性。

目标图至少包含源图中不常见的合法事件顺序，同时保留共享交叉点的历史别名检查。若只是移动格子却让事件顺序分布几乎不变，实验更接近路径重学，未充分测试任务规则的泛化。

分别报告目标适应成本、AUC、最终成功率，以及源采集加全部目标适应的总成本。画出复用到第 1、3、更多张地图时的累计成本，观察源学习费用何时被摊薄。源训练失败也纳入结果，不只迁移成功种子中的最佳自动机。

用独立评估器检查源/目标可达语言上的输出正确性、关键决策处正确性，以及新图是否触发错误合并。原先终点 pairwise precision 不能替代这项检查；也不必以恢复完整的全语言最小机作为开始实验的前提。

## 不可逆性作为第二阶段

最干净的改动是在同一历史歧义交叉点增加“提交选择”：正确提交继续，错误提交进入失败终态。先检验任务层面的不可恢复错误，再考虑单向门、消耗品等物理不可逆状态。

在可逆与不可逆两个任务版本中分别重复相同的迁移对照。**每个版本内部的 A 和 B 必须执行同一套规则。** 不能在源图忽略错误、目标图将错误变成失败，却仍称作只换地图。

主要新增指标为首次不可逆失败前的成功率、失败总次数、每次成功对应的失败成本，以及任务机预测为安全却实际失败的次数。严格区分记忆错误与导航错误。错误合并可能让迁移比从头学习更差，这也是重要结果。

若再加入门锁、库存等会改变动力学的变量，物理状态需包含这些变量；否则跨任务状态反事实复用实际转移可能不合法。硬屏蔽作为独立方法轴，以同信息的手写历史屏蔽器为公平参照。

## 可争取的研究结论

“自动机可表达任务、可用于迁移”已有相关研究，不宜作为唯一新颖性主张。本项目更有辨识度的问题是：有限、有偏的源环境证据下，什么样的任务模型能迁移；模型错误如何随目标图的事件顺序变化暴露；哪些目标反馈值得用来修订它；源学习成本和不可逆失败代价何时值得支付。

如果这条路径成立，贡献可以围绕源证据覆盖、模型保守性、目标修订成本与复用次数建立。它比继续追求一张 oracle 距离表的性能更贴近项目最初的设想。
