# Stage 8 工作复核：总结、分析与下一步建议

日期：2026-09-10。范围：阅读第三、四、五步报告及后续查询选择更正，核对当前模拟器、任务族、运行器、测试和原始结果。未修改实验源码、原报告或原始数据；只新增本复核目录。现有18项测试重跑通过；另外执行了两个合并反例和一个势函数检查，并抽取第五步四个方法配置复跑，轨迹哈希、检查点、first90、AUC及精度均与存档一致。这不是整套历史实验的重现。

**判断：当前数据支持“紧凑的正确表示有价值、目标导向探索和塑形能改善当前学习器”，但还不能支持“合并规则已排除问题、失败完全由证据覆盖造成”，也不能据此关闭所有学习压缩路线。** 两处合并实现问题和一处塑形实现与描述不一致，需要先处理。

## 1. 已完成工作的主线

1. 从纯无序任务改为“无序子目标 + 随机敏感对决定顺序位 + 共享桥段 + 分支后缀”。这让词袋不再普遍充分，也把必要记忆与可合并的历史区分开。
2. 从开阔房间改成小型走廊，解决物理探索难度压过任务表示差异的问题；最终采用六个固定任务/地图台阶，换训练随机种子确认。
3. 用真实最小自动机作为参考，确认压缩潜力能带来样本效率差异。这是已知正确抽象的收益，不是学会抽象的收益，也不要求TL源语言。
4. 实现证据驱动合并、配额、修订和值处理，测到学习合并的性能退化。
5. 加入目标条件技能辅助的探索及势函数塑形，并通过随机目标、未收集标签、按历史计账等对照修正最初的机制解释。

最后一步的更正有价值：目标导向探索的总收益不能全部算到结构推断名下；其中相当部分来自简单的episode内事件记忆。

## 2. 哪些结果能从正式数据复核

以下来自 `results/full/raw.jsonl`，六个台阶各32个配对训练种子，共2112组。表中步数是第一次达到90%的封顶均值，必须与AUC、最终成功率一起读。

| 条件 | 首次90%步数 | AUC | 最终成功率 |
| --- | ---: | ---: | ---: |
| 完整历史 | 32,187.5 | 0.89086 | 1.00000 |
| 真实最小状态 | 13,354.2 | 0.94804 | 1.00000 |
| 完整历史 + 最少尝试目标探索 | 11,692.7 | 0.96138 | 1.00000 |
| 完整历史 + 学习版塑形 | 10,677.1 | 0.95883 | 1.00000 |
| 完整历史 + 塑形 + 探索 | 5,432.3 | 0.98248 | 1.00000 |
| 真实最小状态 + 塑形 + 探索 | 3,765.6 | 0.98810 | 1.00000 |
| 学习合并 + 同样探索 | 11,750.0 | 0.87113 | 0.89497 |

因此可以保留：正确状态抽象有收益；探索与塑形的组合有效；当前学习合并臂损害后期性能。不能把“首次90%近似相同”写成“合并贡献精确为零”，更准确是本设置下未见首次达标收益，且长期指标明显更差。

查询选择批次是另一组种子，不能混用绝对值。`query_baseline.json` 与 `query_strategy.json` 在beta=.15下得到：31,250 → 随机目标24,411.5 → 未收集标签14,979.2 → 最少尝试目标11,744.8 → separating11,755.2。最后两者非常接近，但并不逐位相同；把区间保留两位后写成[1.00,1.00]不代表确定性等价。

“fresh”不学习自动机，但代码仍扫描本episode的成功事件历史以维护已收集集合，故应称“简单历史启发式”，不是无记忆或无任务信息基线。所有这些条件都保留准确的逐步progress反馈；基础奖励稀疏不等于任务信息只有终端才可见。

## 3. 必须先修正的三项

### 3.1 合并类没有累计成员证据，确实会忽略已观察到的冲突

位置：`src/compress.cpp:145–178`。`compatible()`把节点换成并查集代表后，只读取代表节点的 `advanced/ignored/succ`；`unite()`没有把其余成员的证据和边合入代表。

反例：A尚未试过事件e，B见过e推进，C见过e被忽略。A、B、C都满足theta=200。先合A、B，再合A、C时，B与C的明确冲突会被漏掉。当前代码的实际输出是：

```
representative_probe conflict=1 merged=1
```

这说明不能把当前失败完全归因于“缺少反例”：反例已经存在，也可能没有被算法保留下来。建议以类内所有成员聚合的证据检查兼容性，使用临时划分试合并，验证整个候选类和所有后继类后才提交。

### 3.2 配额没有覆盖传播合并，报告的精度1.00也与正式数据不符

配额在外层候选i、j上检查，但后继传播没有再次检查theta/quota。两个满足配额的父节点会带着两个不满足配额的后继一起合并。实测：

```
propagation_probe children_meet_quota=0 children_merged=1
```

第五步正文写配额后合并精度1.00；`full`正式数据中 `merged+scarcest` 的平均精度实际为 **0.699293**。逐台阶均值为：

| 台阶 | 合并精度 | 合并召回 |
| --- | ---: | ---: |
| 1.3 | 0.555108 | 0.135979 |
| 1.6 | 1.000000 | 0.255638 |
| 1.8 | 1.000000 | 0.323376 |
| 2.0 | 0.310330 | 0.074641 |
| 2.2 | 0.605744 | 0.205281 |
| 2.6 | 0.724574 | 0.378005 |

所以“安全但极少的合并仍无收益”尚未被这批正式结果建立。当前可以说的是：这个实现即使加入配额，仍有错误合并且影响稳定性。还需逐次记录精度/错误合并；末时刻的精度不能证明训练全程安全。

另外，完整证据对照只枚举选中最优轨迹的前缀，不是任务全部可达成功事件历史。例如台阶1.3只检查28个前缀，而整个任务语言有185个；台阶2.6为76对209。该对照的正结果应限定在这个子集，不能作为通用正确性证明。上述两个反例说明现有“18项通过”仍不足以排除算法缺陷。

### 3.3 学习版塑形没有实现报告描述的首次成功前机制

位置：`src/compress.cpp:232,353–360,509`。`deepest`初始化为0，整个文件没有更新它；在 `solved_length==0` 时，`horizon=max(0,upto)=upto`，所以对任何历史前缀，势函数恒为0。

因此首次成功前学习版塑形没有中间信号。首次成功后它使用成功事件总长度减当前深度，而不是沿已学习图求到接受状态的剩余距离；这更接近“用首次成功校准的进度计数势”。建议增加简单计数势基线，并分别记录首次真实成功之前/之后的塑形量与学习曲线。

不能用目前的两倍性能差直接断言“这正是未知任务长度的成本”：oracle还改变了势的来源和生效时点，且两臂尺度分别是.05与.1。

高尺度失败也不能直接归结为“塑形使frontier成为最优终点”。标准固定势差在相应MDP和终端边界条件下保持最优策略；大尺度可以影响有限样本学习、初始化和数值表现。当前学习势还会在首次成功时改变，而oracle臂没有未知frontier，报告却说两者都崩溃。因此需先查行为停在哪里、是否已见终端、截断处理、势版本变化及值函数的坐标转换。原始理论依据：[Ng等，1999](https://ai.stanford.edu/~ang/papers/shaping-icml99.pdf)。

## 4. 统计与实验解释需要收紧

- **仿射拟合是经验关联，不是成本定律。** 目前用训练结束的 `ids.size()`预测更早的first90；特征数既受表示影响，也受探索轨迹和已发生的学习结果影响，并非独立操纵变量。它也不是访问量加权有效状态数。截距不是直接测到的第一次成功成本，更不能仅凭几条拟合线断言存在所有机制都触及不了的地板。建议记录固定步数处、首次成功处、first90处的访问分布，并用同一轨迹分布投影不同表示作为独立诊断。
- **第三步表内区间有错配。** 从原始数据按现有配对bootstrap函数重算，台阶1.8的历史/自动机比为2.4837，95%区间约[2.4277,2.5405]，不是表中[2.27,2.40]；台阶2.6为2.9469，[2.8559,3.0371]。现有分析脚本先打印window/automaton的区间、再打印history/automaton的点估计，报告似乎混用了两列。
- **覆盖率的分母会变。** 指标只纳入达到theta访问数的已见节点，且探索会改变节点集合，不能用不同策略的一个最终比例直接判定“没有增加结构证据”。beta=.15时query批次random/fresh/scarcest/separating覆盖均值分别约.808/.645/.783/.788，并非所有规则都约.80。建议固定评价节点集，并报告实际区分了多少候选状态对、新增正/负证据数量及每份证据的物理成本。
- **更新账需要完整。** `updates=6×budget`只统计任务Q；第五步每步另有6或7次技能更新，同一台阶各臂相同，故不自动构成该批比较的不公平，但应如实报总数。`revision_updates`是额外重放，代码从主计数中扣出后单列；修订策略比较并未配平总更新数。当前按一个旧成员复制值的transfer也不是JIRP的未来等价状态迁移。[JIRP原论文](https://arxiv.org/abs/1909.05912)明确以状态等价关系为迁移依据。
- **确认的是新训练种子，不是新任务。** 六个地图和敏感对基本固定；这支持该固定基准内的重复性，尚不足以证明未知任务泛化。跨台阶合并置信区间时宜按种子分块重采样，并单列台阶结果。
- **存档不足以还原所有版本。** 新运行器保存源码哈希，但没有每批源码快照、完整参数和不可覆盖输出约束；部分spec的源码哈希与当前源码不同。此次抽取4配置可以复现，但不等于所有旧批次都已验证。

## 5. 我建议的后续顺序

1. **先做修复与小规模复核，不扩大扫描。** 修正类证据累计和后继配额，补两个反例测试；确认势函数的预期定义并补“首次成功前是否非零”的测试；从原始数据重生成报告表，保留此次勘误。
2. **同一份证据上隔离学习器。** 固定原始事件/进展轨迹，比较旧合并器、修复版和oracle划分；记录是否在保留现有冲突的前提下仍无法压缩。这才区分证据不足与推断器丢失证据。闭环阶段再测改变采样的总效果。
3. **做最小且公平的塑形/初始化消融。** 完整历史不塑形、首次成功后计数势、完整任务图距离势；保持尺度、初始化、更新预算可比。把首次成功发现与成功后的学习效率分开，暂不把该效果冠名为自动机推断的收益。
4. **若正确合并仍得不偿失，转向任务相关的足够记忆。** 在明确给定任务族先验的对照中，可以枚举候选敏感对，学习哪一个顺序位有用；与完整历史、词袋和通用合并器公平比较。该路线是在学习任务参数，必须披露家族先验，不能包装成任意自动机学习。
5. **H6放在表示更新语义和预算清楚之后。** 原始回放本来已经按当前表示解析；新的实验应检验“结构修订时额外安排的旧数据更新”相比等量普通回放和正确Q迁移能多做什么。修订前后暂停环境，配平总Bellman更新，才可计算仅旧数据带来的收益。

当前最稳妥的研究表述是：**准确的进展反馈和事件记忆支持有效的探索与训练信号；正确的状态压缩提供进一步收益，但如何稳定地从经验中得到这种压缩仍未解决。** 这既保留了已有实验的价值，也给下一轮留下了可证伪的问题。
