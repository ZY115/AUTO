# Stage 8 第三十二步（P3.5）：可辨识性审计，答案是 0

P3 用错了量词。共享一次付费答案要安全，需要的不是"现有证据没有矛盾"（∃ 一个模型允许两条历史相同），
而是"**所有仍与数据相容的任务模型对这次预测给出同一个答案**"（∀）。这一步量的就是这两者的差。

把 91.3 次冗余查询拆成两部分：

\[ 91.3 = Q_{\text{可辨识}} + Q_{\text{根本歧义}} \]

**结论：可辨识的那部分是 0。** 阶梯里那个框应该填 177：

\[ 1299 \;>\; 215 \;>\; 177 \;>\; \boxed{177} \;>\; 86 \]

## 1. 两个前置事实：任务状态其实非常好区分

24 个族里，每一对真正可区分的任务状态，最短区分后缀的长度：

| 长度 | 对数 | 占比 |
| --- | --- | --- |
| 1 | 16,680 | **96.2%** |
| 2 | 240 | 1.4% |
| ≥3 | 424 | 2.4% |

合计 17,344 对，平均 1.09，最长 8。**96% 的状态对只要观察一个事件就能分开。**
所以 P3 的失败不是因为状态难辨认。

## 2. version-space 参照臂

不给 agent 真自动机，只给它和普通 learner 完全相同的已观察数据 D。用 ASP 编码所有与 D 相容的
任务机：每条已观察历史指派到 k 个潜状态之一，转移函数与输出函数都必须是函数，每一次付过费的
观察都必须被满足，**推进必须改变状态**，**忽略必须是自环**。

对当前要处理的 `(历史 h, 事件 e)`，分别问求解器"存在一个相容模型使答案是推进 / 忽略 / 致命吗"。
只有一个可满足，这次查询就是**本可以免费推断出来的**；两个以上可满足，就是**真歧义**，
不查就没法保证零错误。

回放真实运行的查询日志：第 i 次查询的证据就是前 i−1 次查询的结果。

## 3. 结果：每一档 k、每一段日志，都是 0

| 任务 | 真实最小类 | 假设 k | 核查 | **已确定** | 歧义 | 与真值矛盾 |
| --- | --- | --- | --- | --- | --- | --- |
| c_n3d2m1_4L2a7 | 18 | 9 | 40 | **0** | 40 | 0 |
| | | 18 | 40 | **0** | 40 | 0 |
| | | 22 | 40 | **0** | 40 | 0 |
| c_n4d2m1_4L2a7 | 28 | 14 | 40 | **0** | 40 | 0 |
| | | 28 | 40 | **0** | 40 | 0 |
| | | 32 | 40 | **0** | 40 | 0 |

证据累积也不产生确定性：

| 任务 | 最早 20 条 | 中间 20 条 | 最后 20 条 |
| --- | --- | --- | --- |
| c_n3d2m1_4L2a7（k=18） | 0 确定 / 20 歧义 | 0 / 20 | 0 / 20 |
| c_n4d2m1_4L2a7（k=28） | 0 确定 / 20 歧义 | 0 / 20 | 0 / 20 |

**没有一次查询是可以安全省掉的。**

（一个早期版本在 k=3、4、6 上报出过几次"已确定"，但其中有的与真值矛盾——那是状态数上界
小到把真相排除在外，于是"确定"的是错的。加上"推进必须改变状态"这条约束并用足够大的 k 之后，
矛盾数归零，确定数也归零。）

## 4. 这把 91.3 的分解填满了

\[ 91.3 = \underbrace{\approx 0}_{\text{漏掉的推断}} + \underbrace{\approx 91.3}_{\text{缺少区分性证据}} \]

结合第 1 节：**状态本身只要一个事件就能分开，但 agent 在做这次查询的当口，手上并没有那个事件
在两条历史上的观察。** 所以歧义不是推断能力不足，是**证据本身没有区分性**。

这也正式解释了 P3 为什么必然向左上移动：它省下的每一次查询，都是在两个都合法的模型之间**赌**
了一把，所以漏推进不是实现缺陷，是这条路上不可避免的代价。

**可以写成一个命题**：若两条历史对事件 e 的反馈至少有一个未观察，且当前数据同时相容于
"两者对 e 相同"与"两者对 e 不同"，那么任何只依赖当前数据、不查询 e 就在二者间共享该反馈的
算法，都不能保证零错误。审计说明，在这个设置里**几乎每一次冗余查询都落在这个条件下**。

## 5. 对方向的判断

按预设的判据：**"如果答案只有 15，oracle 的 86 就不是一个可学习目标。"实测是 0。**
所以 86 在当前信息条件下不可达。**177 的准确说法是：在当前 hypothesis class 下、要求零预测错误、且不主动获得额外证据时，观察到的安全界限。** 它不是「数据能做到的最好」这种一般性断言——换一个假设类、或者允许非零风险、或者主动去取证，界限都会动。（第三十三步分别检验了后两条。）

要拿到那 91.3，只有三条路，都不是"更好的推断算法"：

1. **获得更多观测**——也就是主动去制造区分性证据。第 1 节说最短区分后缀 96% 只有 1 个事件，
   所以这条路的成本可能很低，这是唯一还开着的门。
2. **加入关于任务机器的结构假设**（比如无环、或已知任务模板），把假设空间压小。
3. **接受非零风险**——就是 P3 做的，代价已经量过。

**P4 保持关闭，理由已经变了**：不是"没找到好算法"，而是"在当前信息条件下不存在好算法"。

## 6. 限制

- 两个任务、每个一个种子、每个核查 60 条查询（早中晚各 20），不是全量。
- 假设空间是"状态数 ≤ k 的确定性机器，推进改变状态，忽略自环"。**更强的先验会缩小它**，
  上面的第 2 条路正是这个意思；这个审计给的是该假设空间下的答案，不是普适下界。
- ASP 编码的"所有相容模型"只强到所编码的约束为止。
