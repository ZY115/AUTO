# Stage 8 第二十步：最小跨地图对照，结构在这个条件下没有额外价值

路线第三步。任务语义与事件标签在源图目标图之间不变；目标图上的导航技能、地图模型、全部值表一律重置。只有任务知识过河，各组的差别只在**那份知识是什么、以及信到什么程度**。

| 组别 | 过河的东西 |
| --- | --- |
| 从零学习 | 没有 |
| 迁移字典 | 冻结的源图前缀树，按**精确历史**查 |
| 直接用结构 | 同一棵树，折进**保守划分**的类 |
| 直接用激进结构 | 同一棵树，折进**过度合并**的划分 |
| 选择性使用 | 同一棵树与两个划分，分层：亲历证据优先，其次保守类能排除什么，过度合并的额外作答只在从未观察到致命事件时才用 |
| 真实结构参照 | 正确的任务机 |

第二到五组共用同一批冻结数据，所以除了"怎么用"之外没有任何差别。验证像任何一步一样花目标预算，没有免费查询。

结论先说：**你设的失败判据触发了。真实任务机相对同证据字典是 1.000 [0.946, 1.059]，没有任何额外价值。** 而且更要紧的是，这个实验在开跑之前天花板就只有 1.05 倍。

## 2. 你设的两条判据，逐条回答

**"第四组能否同时超过迁移字典和直接使用结构？"** 超过了直接使用结构，**1.161 [1.125, 1.196]**，分层规则确实有效；但没有超过迁移字典，**0.838 [0.769, 0.915]**。**答案是否。**

**"如果完整结构不能胜过同证据字典，就应明确承认它在这个条件下没有额外价值。"** 真实任务机相对同证据字典是 **1.000 [0.946, 1.059]**。**明确承认：在这个条件下，完整任务结构相对同证据历史字典没有额外价值。**

## 3. 更要紧的一条：这个实验的天花板是 1.05 倍

从零学习 922 步，真实结构 878 步。**真实结构相对从零学习只有 1.051 [0.989, 1.120]，区间含 1。** 也就是说：无论迁移什么、怎么用，可赢的全部空间只有 5%。

这不是实验失败，是**实验一开始就问不了这个问题**。项目自己的元规则是"先算天花板再造机制"，这一次我没有在动手前算，应该算。天花板就是 `真实结构 ÷ 从零学习`，它是免费的一次计算。

**为什么天花板这么低。** 目标地图上的任务用目标读法 900 步就学会了。第十五步之所以是个大结果，正是因为目标读法把学任务这件事变得极快；而这同一个性质，把"提前知道任务"值多少钱压到了几乎为零。**让第十五步的结论变大的机制，正是让迁移问题变得不值得问的机制。**

按顺序重叠度分档，天花板随两图差异变大而变大，但幅度仍小：

| 重叠度 | 从零学习 | 真实结构 | 天花板 |
| --- | --- | --- | --- |
| 1.0 | 856 | 838 | 1.02 |
| 0.5 | 725 | 712 | 1.02 |
| 0.33 | 988 | 938 | 1.05 |
| 0.0 | 1,188 | 1,062 | 1.12 |

## 4. 把源图采样计入成本

| 比较（总成本 = 目标达标步数 + 40,000 源步） | 比值 |
| --- | --- |
| 迁移字典 ÷ 从零学习 | **0.023 [0.020, 0.025]** |
| 选择性使用 ÷ 从零学习 | 0.022 [0.020, 0.025] |

**花 40,000 步在源图上，为的是在目标图上省 44 步。** 按总成本算，迁移比不迁移差 43 倍。这个数字只在这个族、这个预算下成立，但它说明"迁移是否划算"必须连采样成本一起报，否则连方向都会搞反。

## 5. 一条独立于天花板的发现：合并会稀释亲历证据

**直接用结构比用字典慢 0.722 [0.659, 0.799]**，激进划分更是 0.041。这不是天花板问题，因为两者用的是同一批证据。

原因是：在 agent **有记录**的历史上，精确的逐历史证据是最好的；折进一个类等于把这个类里其他成员看到的东西掺进来，而一次错误合并掺进来的是假的。归纳是给没有记录的历史用的，不是给有记录的历史用的。

这正是分层规则起作用的地方：**选择性使用把亲历证据放在第一层，相对直接用结构赢回 1.161 [1.125, 1.196]。** 规则本身是对的，只是在这个族里它上面没有空间。

## 6. 途中两个实现陷阱

**第一个，试点抓到的：几个臂一开始在"证据来源"之外还差了"并列打破规则"。** `learned` 取推进次数最多的事件，而我新写的类读法取所有推进过的事件。那样比较出来的是打破规则，不是证据来源。给划分加了类级推进计数之后才可比。

**第二个，老毛病：两处 `replace` 静默没匹配上**，构建通过、结果不变，看起来像"改了没用"。项目历史上已经因为这个错过一次。现在每次改完都 grep 一下确认。

## 7. 下一步该往哪走

这一步给的不是"迁移没用"，是**"要研究迁移，得先有空间"**。这个族里目标读法把空间抹平了。三条可走：

1. **换一个即使用目标读法也慢的任务族**：更长的任务、更多事件、更稀疏的布局，让从零学习要几万步而不是九百步。天花板可以先离线算，不必训练。
2. **去不可逆族问同一个问题**：那里学到的目标路由器相对真实的是 0.75，比这里的 1.00 有空间，虽然也不大。
3. **承认这条线在当前任务族里到此为止**，把力气放回"覆盖率"——第十九步测出，即使真划分加闭世界补全，仍有 0.67 的新历史折不进任何类，而定向采集让它更糟。那是目前唯一一个既大又没被解释的缺口。

我建议先做第 1 条的**离线部分**：只算天花板，不训练。它很便宜，而且能直接决定第 2、3 条值不值得做。
