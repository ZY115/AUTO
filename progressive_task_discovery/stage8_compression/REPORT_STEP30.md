# Stage 8 第三十步（P1 + P2）：归属阶梯，以及缺口的分解

排错阶段结束。这一步只做一件事：**固定控制器、固定查询规则、固定环境与训练参数，
只改变"一次查询的答案分享给谁"。** 查询规则用最机械的一种：
`(归属状态, 事件)` 第一次出现就问，以后复用。不掺 novel / aligned / decision 任何启发式。

## 1. 归属阶梯

24 个族 × 6 个种子，环境预算 200,000，查询预算 2,000（实际不受限）。

| 归档键 | 查询 | = 必要 | + 冗余 | 过细占比 | 误用缓存 | 漏推进 | 类数/节点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 完整可见前缀 | 1,298.7 | 85.3 | 1,213.4 | **93.4%** | 0.0 | 0.0 | — |
| **进展历史节点（现行）** | **176.9** | 85.6 | 91.3 | **51.6%** | 0.0 | 0.0 | — |
| 学到的合并类 | 214.7 | 81.7 | 132.9 | 61.9% | **304.2** | **3.8** | 45/98 |
| **真实任务状态（上限）** | **85.6** | 85.6 | **0.0** | **0%** | 0.0 | 0.0 | — |

比值（块=任务族，24 块）：

| 比较 | 值 |
| --- | --- |
| 完整前缀 ÷ node | 7.34 [6.99, 7.71]（更差） |
| **node ÷ oracle** | **2.07 [1.94, 2.17]** ← 这是待缩小的缺口 |
| **node ÷ 学到的合并** | **0.82 [0.80, 0.85]**（学到的合并更差） |
| 学到的合并 ÷ oracle | 2.51 [2.32, 2.68] |

**"必要查询"在四个键上都是 85 左右**，这正是任务本身的信息量——agent 遇到的不同
`(真实任务状态, 事件)` 对的数量。它对归属方式不变，这验证了这个分解本身。

## 2. 缺口的分解：全部是过细，不是过合并

- **过细（over-splitting）**：现行 node 的 176.9 次查询里有 **91.3 次是冗余的**，
  即那个 `(真实状态, 事件)` 对已经在别的归属状态下被买过。**这 51.6% 就是全部缺口。**
- **不安全复用（over-merging）**：在不受限预算下，完整前缀、node、真实状态**三者的误用
  缓存都是 0.0**。也就是说**过合并在这里没有任何代价，因为现行规则根本不过合并**。
- **决策相关的混淆**：只有"学到的合并类"产生了它——304.2 次误用缓存，其中 3.8 次是
  漏掉推进（会让历史与任务错位的那一类）。

所以第二个指标目前是空的：**不是我们测出过合并很安全，而是现行方法从不过合并。**
这条要等 P3 的学习型抽象出来之后才有内容。

## 3. 一个比预期更差的结果：现有的合并作为归属键是负的

**学到的合并类不是"捕获了一部分机会"，而是比基线更差**：0.82 [0.80, 0.85]。
它同时多花查询（214.7 对 176.9）、引入 304 次误用缓存、并且第一次出现了漏推进。

多花查询的原因可以定位：合并改变了信念，也就改变了轨迹——节点数从 67 涨到 98，
agent 走到了更多不同的历史上，于是 `(节点, 事件)` 对本身变多了。

顺带查明了一件事：在 `--merge-rule sweep --theta 20 --quota 1` 下划分**根本不合并**
（73 类 / 73 节点），所以早先看到的"与基线逐位相同"不是结论而是没生效。改用 EDSM 之后
才真正合并（27 类 / 84 节点，192 → 179 次查询，误用 4 次，漏推进 0）。**在安全的设置下
现有规则只能把 192 推到 179；把阈值放开能到 165，但代价是 1,724 次漏推进。**

## 4. 研究空间，现在是一个确切的区间

\[
\text{完整前缀 } 1299
\;>\;
\text{学到的合并 } 215
\;>\;
\text{进展节点 } 177
\;>\;
\;?\;
\;>\;
\text{真实状态 } 86
\]

**要缩小的是 177 → 86，即 2.07 [1.94, 2.17] 倍，而现有的结构学习在这条线上是负贡献。**
P3 要做的学习型抽象，唯一的任务就是在不引入漏推进的前提下把 177 往 86 推。

两个必须同时盯住的指标已经就位：**冗余查询数**（过细）和**漏推进数**（危险的过合并）。
现行 node 是 (91.3, 0.0)，真实状态是 (0.0, 0.0)，学到的合并是 (132.9, 3.8)。
一个合格的学习型抽象必须落在这三者围出的左下方向。
