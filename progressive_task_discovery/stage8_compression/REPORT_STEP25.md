# Stage 8 第二十五步：21% 推不上去，除非愿意付代价

第二十四步用一条很粗的规则省下 21% 的查询：类对这个对已经有意见就不问。这一步试着把它做大，三条路都试了，结论是**在"结果不能退化"这个约束下，21% 就是前沿**。

三条路各自的问题都很具体，值得单独记。

## 1. 三条路

| 规则 | 做法 |
| --- | --- |
| arrival | 每个没查过的对都查（基线） |
| novel | 类对这个对有任何明确意见就不问（第二十四步的规则） |
| **aligned** | **只在类说"不推进"时不问**，让"不问"和"当它没推进"这两件事一致 |
| **closed** | aligned 再加闭世界补全：某个类见过东西推进，则这个类里没见过推进的事件断言为不推进 |

各自再交叉三种被查阅的划分（保守、过度合并、**真划分**作为特权上界）和两档支持度阈值。24 个族 × 4 个种子 × 2 档预算。

## 2. 前沿

查询预算 320，24 个族 × 4 个种子：

| 规则 | 用掉查询 | 达标步数 | 解出 | 相对 arrival 省查询 |
| --- | --- | --- | --- | --- |
| arrival / 保守 | 173.1 | 1,255 | 96/96 | 1.00 |
| **novel / 保守** | **144.2** | **1,255** | **96/96** | **1.20 [1.17, 1.23]** |
| aligned / 保守 | 156.9 | 1,255 | 96/96 | 1.10 [1.09, 1.12] |
| closed / 保守 | 85.2 | 30,242 | **81/96** | 2.03 [1.86, 2.22] |
| closed / 真划分 | 52.5 | 47,445 | **74/96** | 3.30 [2.98, 3.60] |

**只有 novel 和 aligned 在结果不退化的前提下省钱，而 novel 省得更多。** closed 省 2 到 3.3 倍，但达标步数变成 0.04 倍、解出率从 96/96 掉到 81/96 甚至 74/96。

## 3. 三条负面结果，每条都有具体原因

**第一，我那条"更有道理"的修正反而更差。** `aligned` 的想法是：不问就等于信"没推进"，所以只该在类也说"不推进"的地方不问；类说"推进"的地方恰恰最该花钱。逻辑成立，实测 1.10 倍，**不如粗规则的 1.20 倍**。原因是那些"类说推进"的对，多数出现在 agent 已经知道另一个推进事件的节点上，问不问都不改变它的行为。**逻辑上更该问的地方，实际上不影响决策。**

**第二，闭世界补全是真省钱，但不是白省。** 单个族上的探针显示它能把 192 次查询压到 50 次而且更快，放到 24 个族上就不成立了：省 2.03 倍，解出率掉 15 个族。第十九步已经量过它的错法——把推进事件判成 ignore——在这里的后果是 agent 漏掉一次推进、历史与真实状态错位，也就是第二十四步记下的那个失效模式。**单族探针不能代替网格，这次差点又栽在同一件事上。**

**第三，更好的划分不会带来更好的"不问"规则。** 真划分配 novel 只解出 32/96，配 aligned 57/96，都比保守划分的 96/96 差得多。真划分把 agent 在节点层面分开处理的历史合并在一起，于是它的判断被自信地用在 agent belief 状态并不相同的节点上，让 agent 跳过了本该问的问题。**这是这个项目反复出现的模式又一次出现：把结构做得更对，不等于把它用得更好。**

## 4. 如果愿意付代价，代价是多少

把查询折成环境步，总成本 = 达标步数 + c × 查询次数：

| 规则 | 与 arrival 的交叉点 | 但是 |
| --- | --- | --- |
| closed / 保守 | 每次查询 330 步 [159, 518] | 只解出 81/96 |
| closed / 真划分 | 每次查询 383 步 [216, 590] | 只解出 74/96 |

**总成本口径会把解出率藏起来。** 一个在 15 个族上永远达不到 90% 的规则，不能因为总成本更低就说它更好。所以这两行只作为定价参考，不作为推荐。

## 5. 这一步的结论

**21% 是这个设置下"结果不退化"的查询节省前沿。** 三种把它做大的尝试，一种更差，两种要拿解出率去换。

这不改变第二十四步的主张，反而把它收紧了：结构买的是**更少的提问**，幅度是 1.20 [1.17, 1.23] 倍，而且这个幅度已经接近这套机制能给的上限。要再往上，需要的不是更好的划分或更强的补全，而是一个能让 agent **知道自己漏掉了一次推进**的接口——现在它没有任何办法发现错位，这是第二十四步和这一步共同指向的同一个缺口。
