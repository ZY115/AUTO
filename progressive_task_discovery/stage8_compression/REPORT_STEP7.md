# Stage 8 第七步：以审稿人视角复核第六步，并追到底

第六步的头条是"任务图乘地图的势相对进度深度势是 3.85 倍"。以审稿人视角看，这个说法有一个致命隐患和一个混杂，都必须先排掉；排掉之后剩下的结论比原来的窄，但可信得多；顺着它做下去得到一个明确的负结果。

## 1. 审稿人最该问的一条：那不就是把最优值函数交给了它

乘积距离是从任务状态与格子出发到接受所需的精确环境步数。在步成本 −0.01、折扣 0.99 下，最优值约为 −0.01d 加 R·0.99^d，与 −scale·d 单调同构。**所以乘积势基本就是最优值函数**，用它做塑形当然快。这不是关于自动机的结论。

处理办法是把它拆开，看每一个坐标各自值多少。十二个任务、32 个新种子、每种势各自在开发集选尺度：

| 势 | 知道什么 | 达标步数 | 首次成功 | AUC |
| --- | --- | --- | --- | --- |
| 不塑形 | | 29,039 | 5,193 | 0.904 |
| 只知位置 | 地图，按任务状态求边缘 | 29,763 | 4,258 | 0.907 |
| 打乱表空对照 | 结构对，但配到错的任务状态 | 43,872 | 5,253 | 0.878 |
| 进度深度 | 进度计数与已见最深 | 4,294 | 1,132 | 0.990 |
| 任务图，转移单位 | 真实任务机上的转移数 | 5,964 | 1,272 | 0.986 |
| 任务状态，步数单位 | 同上但换成步数 | 5,797 | 1,324 | 0.985 |
| 错误任务的乘积表 | 地图与目标集合，分支判反 | 2,862 | 314 | 0.997 |
| 正确乘积表 | 全部 | 1,122 | 278 | 1.000 |

逐层，按任务成块的配对 bootstrap，12 个块：

| 这一层加了什么 | 倍数 | 95% 区间 |
| --- | --- | --- |
| 只加位置 | 0.98 | [0.93, 1.06] |
| 结构对但配错状态 | 0.66 | [0.60, 0.72] |
| 进度深度 | 6.76 | [5.28, 8.35] |
| 任务状态换成步数单位 | 0.74 | [0.67, 0.81] |
| 再加位置，但分支判错 | 2.03 | [1.69, 2.50] |
| **再把分支判对** | **2.55** | **[1.95, 3.15]** |

四条读法：

**任一坐标单独都不行。** 只知位置是 0.98，什么都不是。只知任务状态，不论用转移还是步数为单位，都比朴素的进度深度势更差，0.74。

**换单位不是原因。** 我原来担心"任务图用转移、乘积用步数"是个混杂，把任务状态换成步数单位后仍然是 0.74，所以不是单位问题。

**空对照表现得像空对照。** 把同一批数字配到打乱后的任务状态上，比不塑形还差，0.66。所以这不是"任何有结构的势都有用"。

**真正只有自动机能表示的那部分，值 2.55 倍。** 错误任务的乘积表在无序段和桥段上都是对的，只把分支判反，它已经拿到 2.03 倍；把分支判对再加 2.55 倍。分支由很多步之前的一个事件决定，位置和进度计数都读不出来，这正是需要任务记忆的那一部分。这个数字也挡住了开头那条反驳：错误任务的乘积表同样是某个任务的最优值函数，却只拿到 2,862。

## 2. 顺着往下：可学习的乘积势能不能拿到这份空间

正确乘积表是特权参照。做了两个只用 agent 自己能观测到的东西的版本。

**版本一，从成功轨迹反向计数。** 每次完整成功后沿轨迹倒推，记录每个"任务节点加格子"到成功的步数，取历次最小值；没有记录时回退到深度势。

实现中发现并修掉一个单位错误：学到的表是步数，回退是事件数，同一个尺度下差两三倍，进出已学区域时势会突跳。用 agent 自己测得的"每个事件平均几步"换算之后才可比。

**版本二，从学到的地图与已发现的任务前缀树上计算。** 每走一步就免费得到一条地图边，任务边由进度反馈确认；在两者的乘积上做反向可达。目标在出现过接受节点后是接受节点，之前是已发现的最深节点。

十二个任务的开发集结果：

| 势 | 达标步数 | 首次成功 |
| --- | --- | --- |
| 进度深度 | 4,281 | 1,144 |
| 可学习乘积，反向计数 | 11,062 | 1,099 |
| 计算乘积，向 frontier 反向可达 | 10,438 | 2,192 |
| 正确乘积，特权 | 1,125 | 276 |

**两个版本都比朴素的深度势更差**，原因互补而且都可解释：

反向计数在第一次成功之前没有任何数据，所以那一段它**就是**深度势，首次成功 1,099 与深度势的 1,144 相同。而乘积势的优势几乎全在这一段，276 对 1,132。

向 frontier 反向可达在已知最深处把势取成 0，于是那里成了吸引子，到了就不划算再走，首次成功反而退到 2,192。这正是很早的设计文档里预测过的 frontier 停滞，这次以另一种形式出现。

## 3. 现在能说什么

**乘积势的优势，几乎全部来自"知道到一个从未到达过的目标还有多远"。** 从已发现结构里构造不出这个量：没成功过就没有目标，任何以 frontier 代替目标的做法都会在 frontier 上造出吸引子。这给"结构导出的塑形"划了一条上界，而这条上界与推断质量无关。

**同时，需要任务记忆的那部分结构确实值钱，2.55 倍**，前提是你已经有了地图那一半。

## 4. 不能说什么

正确乘积势是特权参照，标的是上限不是方法。全部结论限于这一族任务、这一族走廊地图、无噪声、表格式学习、12 个固定任务作为块。两个可学习版本各自只试了一种设计，说明的是"这两种做法拿不到"，不是"任何做法都拿不到"。
