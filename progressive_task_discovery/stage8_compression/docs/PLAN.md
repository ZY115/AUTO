# 3. 环境改动

## 3.1 奖励稀疏化

取消每次正确进展加一。

```
r_t = R_success   若整条任务完成
r_t = -c          其余每步
```

进度反馈保留，但不是奖励。每步环境输出物理位置、当前事件标签、是否产生合法进展、稀疏奖励四项。所有方法看到完全相同的这四项，方法之间只允许在如何保存和利用上不同。

## 3.2 必须重调的两个参数

原 pipeline 用 gamma=0.98。k=12 时最短路径 133 步，终端信号传回起点只剩百分之七，稀疏化之后这条会直接压死整轮。开发阶段必须扫：

- gamma 取 0.98、0.99、0.995
- R_success 与路径总成本 c·L 的比值取 0.5、2、8

冻结一组进正式实验，并记录零初始化在该组下是否仍然提供乐观性。这一步不做完不要往下走。

## 3.3 预算与删失

开发阶段先查 50k、100k、200k 三档，确认不是大面积右删失，再冻结一个正式预算。稀疏条件下主指标改为成功率 AUC 和最终成功率，达标步数作为附带并如实标注删失。

# 4. 任务族：无序子任务加共享后缀

## 4.1 任务

n 个子目标任意顺序全部完成，随后固定后缀 D_1 到 D_m。真实自动机的无序段状态是已完成集合，后缀段是链。

## 4.2 静态单点地图上的不可实现性（已确认）

若每个事件标签只对应一个格子，到达首个事件后所在位置固定，剩余最优顺序与起点无关。因此仅靠改变起点最多强制出 n 种唯一最优顺序，达不到 n!。**原稿要求覆盖全部 n! 排列的写法作废，H(n)/2^n 与 n! 两个公式都不再用作横轴。**

## 4.3 修复：每个标签允许多个物理实例

同一事件标签放在 L 个不同格子，进入任一格子即触发该事件。首个事件在哪个实例被触发取决于起点，触发后位置不同，剩余最优顺序随之不同，4.2 的限制被解除。

不引入传送、随机动力学或演示。技能仍为 Q_skill(s,g,a)，导航到最近的同标签实例，定义不变。

**必须同时保留漏斗。** 所有历史在进入后缀之前汇入同一交叉点，在该点上位置与进度计数在各历史之间完全相同。这是 Stage 7 已验证的歧义见证，多实例化之后必须重跑，否则物理位置本身泄露历史。

## 4.4 任务族：为什么必须随实例随机

**分母的判定标准。** agent 在看到隐藏任务之前就要选定表示，所以这个表示必须对任务族里的每一个实例都充分。因此分母是**族内充分且状态数最少**的通用特征，分子是当前这一个实例的最小自动机。用别的规则挑分母都会高估收益。

已经用纯组合的方式验过三个族，不涉及任何训练：

| 族 | 定义 | 诚实比 n=3 / 4 / 5 |
| --- | --- | --- |
| A | 纯无序，固定族 | 1.00 / 1.00 / 1.00 |
| B | 敏感对随实例随机 | 1.69 / 3.70 / 9.72 |
| C | B 再加长度 4 的共享桥段 | 2.19 / 5.84 / 17.61 |

族 A 作废：词袋族内充分，且恰好等于最小自动机，无论 n 多大。固定一个敏感对也不行，因为"词袋加上那两个谁先"同样可以事先写下来。

**族 C 是本阶段采用的族。** 每个实例随机抽一个敏感对，谁先完成决定后缀的分支；分支之前插入长度 d 的共享桥段。两条分支的首个标签必须不同，否则实例其实没有分支，会悄悄退回族 A。

**设计规则，已在所有试过的格子上成立：** 最小充分窗口宽度等于 n+d−1。桥段每加长一格，分母就更靠近完整历史。

推荐阶梯，任务长度 n+d+m 全部不超过 12：

| n | d | 诚实比 | n | d | 诚实比 |
| --- | --- | --- | --- | --- | --- |
| 3 | 0 | 1.69 | 4 | 4 | 5.84 |
| 3 | 2 | 2.00 | 4 | 6 | 6.54 |
| 3 | 4 | 2.19 | 5 | 0 | 9.72 |
| 4 | 0 | 3.70 | 5 | 2 | 14.00 |
| 4 | 2 | 4.93 | 5 | 4 | 17.61 |

阶梯顶端分母有 898 个任务特征状态，在冻结预算下多半学不完。那些格子只给出较弱的结论，即通用基线失败而自动机成功，不给出比值，按 Stage 7 报计数臂的方式如实标注右删失。

## 4.5 旧的两个变体，已被族 C 取代

**变体 A，纯无序。** n 个子目标任意顺序，随后固定后缀。已确认此族中已完成事件的词袋恰好等于最小自动机，五个布局的 bag/|Q| 全为 1.00。因此变体 A 无法区分"学到的合并"与"换一个通用特征"，它只能作为上界情形保留，并且必须同时跑词袋臂，标注为任务族先验。

**变体 B，加一个顺序位。** 后缀走哪一支取决于两个指定无序标签中谁先完成。此时词袋永不充分；m 大于等于 2 时任何有界窗口也不充分，因为决定性证据比任何窗口宽度都更早。压缩相对完整历史仍然保留。**H4 的主实验用变体 B。**

## 4.6 压缩比改为实测，并且分母必须诚实

给定地图与起点集合，用地图与真实自动机的乘积做精确 DP，枚举每个起点的最优轨迹，直接得到：

- 实测历史状态数：全部最优轨迹产生的不同成功事件前缀数
- 实测自动机状态数：这些前缀对应的不同真实任务状态数
- 实测压缩比：两者之比

地图设计因此是一次离线搜索：在候选布局上枚举，挑出实测压缩比落在目标档位的布局。搜索脚本输出与布局一起存档，跑之前作为测试。

变体 B 可达口径下的诚实比，n 取 3、4，m 取 0、2、4、8：1.60、2.00、2.22、2.46、3.25、4.71、5.75、7.14。n=2 试点已确认 m=16 超出冻结的稀疏预算，故 m 上限为 8。

两个旋钮：

| 旋钮 | 作用 | 代价 |
| --- | --- | --- |
| 每标签实例数 L | 抬高可强制的排列数，上限 n! | 事件格子增多，须重跑漏斗检查 |
| 共享后缀长度 m | 使实测比逼近其上限 | 路径变长，稀疏奖励下信号衰减加重 |

优先用 L 抬上限，m 保持在第 3.2 节稀疏奖励扫描确认可学的范围内。某档搜索失败就如实报告该档不可达。

n 取 2、3、4。不扫 n=5、6。

## 4.7 地图约束

1. 每个子目标从多个任务状态可达，路由不由地图强制。
2. 所有历史在进入后缀前汇入同一交叉点，该点上位置与进度计数不区分历史。穷举验证。
3. 从整个起点集合看没有普遍最优排列，从每个单独起点看恰有一个最优排列。穷举验证。
4. **区分见证与合并两类检查。** 见证是"必须区分"：无序段未完成时，存在位置相同、进度计数相同、已完成集合不同的可达历史对，w 低于最小充分宽度的每个窗口都要给出这样一对。合并是"可以合并"：漏斗处各历史已完成同一组子目标，对应同一个真实任务状态，正确的学习器必须把它们并成一个。两者位置可以是同一个格子的不同深度，但结论相反，不能混写。
5. **正对照。** 在变体 A 中 w=n−1 加计数是充分的，必须验证其充分而不是要求其失败。变体 B 中 m 大于等于 2 时应验证不存在充分的有界窗口。
6. 同地图语义对照：地图完全不变，任务改成固定顺序，压缩机会消失。

均衡评价下成功率是 1/m_start 的整数倍。m_start=6 时 90% 门槛等于要求 6/6。这一点写进指标定义。

# 6. 结构学习器

## 6.1 前缀学习器

在线记录成功事件前缀，构成前缀树。作为 baseline 保留，Stage 7 已验证它与完整历史逐动作一致。

## 6.2 合并规则

两段历史在下列证据完全一致时建立合并候选：

1. 已观察到的可行下一进展事件集合相同
2. 进展转换签名相同
3. 已观察后继等价

学习器知道事件词表，不知道真实顺序、哪些事件可交换、真实状态数、合并位置。

## 6.3 高精度需要一个证据阈值

"证据完全一致"不足以保证精度：观察不足时两个状态可能在已见续接上一致而在未见续接上不同。因此合并需要**每个状态的最小观察次数阈值**，该阈值是超参数，必须在开发集冻结，并同时报精度和首次正确合并时间。阈值调高精度上升、延迟上升，这个取舍要画出来。

## 6.4 延迟的代价要单独归因

保守规则意味着合并发生得晚，收益可能只是因为来得晚而变小。用 oracle 最小状态臂做参照，两者差距即结构发现延迟的成本，不要把它算进"合并无效"。

# 8. H4 的定量预测（预注册）

不是"合并更快"，而是：

```
不用技能的臂:  steps(D) / steps(M)  ≈  实测状态数(D) / 实测状态数(M)
```

D 是最小的充分通用表示，按第 4.5 节在可达口径上选出，不是完整历史。用完整历史当分母会高估收益，变体 A 上高估到两倍以上。

依据是 Stage 7 已测的四个格子，步数比与状态数比在百分之十以内。**实测状态数指访问量加权的有效状态数，不是组合数。** 因此必须新增每个任务特征状态的访问计数埋点，这一项在原稿的指标表里没有，缺了就无法区分名义压缩和实际压缩。

主图横轴用实测压缩比，不用名义压缩比。名义值作为第二条曲线并排画，两者分岔本身是结果。

# 9. H5：塑形

基础奖励恒为稀疏项。内部训练奖励加势差项，势取当前任务状态到接受状态的估计剩余转换数的负值。

**frontier 必须单独标记，不能当成接受状态。** 否则会出现稳定策略停在 frontier。正式实现前做一个玩具测试：新转换发现前后，frontier 塑形不得产生停在 frontier 的稳定贪心策略。

回放缓冲区**不存塑形后的奖励**，也不存任务状态标签。原因是结构修订会改变任务状态本身，只改奖励不改标签等于没有用上新抽象。缓冲区存：物理状态、动作、后继物理状态、事件、进展位、基础奖励、episode 号、时刻。训练时按当前结构动态重算任务状态与势。

---

# 10. H6：追溯重解析

结构版本化：每次加边、合并、拆分、改边生成新版本，记录时刻、旧版本、新版本、原因、受影响状态与转换、被重解析的缓冲区行数。

因果实验：每发现一个重要新转换或合并时，暂停环境交互，只用发现之前的缓冲区做固定次数更新，重新评价策略。暂停期不消耗环境步数但消耗更新次数，这些更新必须计入配平账。

三个新指标：

- 追回样本比例：发现前的转移中，能产生新有效更新的比例
- 仅旧数据回放带来的性能增量
- 环境等价节省：不用旧数据时，达到同等性能需要多少新的环境转移

# 15. Go / No-Go

**Strong Go A**：实测压缩比上升时，完整历史与合并的步数比显著上升，且学习到的状态数收敛到真实最小状态数。主贡献候选为状态抽象。

**Strong Go B**：结构修订后仅用旧数据重解析回放即显著提升策略，且优于重置与单纯 Q 迁移。主贡献候选为追溯结构重标注。此项在写论文前必须与 JIRP 的等价状态迁移和奖励机的反事实经验做正面比较，现在不能声称新颖。

**Strong Go C**：四层大体逐层收益。主张改为自动机对 RL 有多个可分离的作用。

**Weak Go**：合并约等于完整历史，但技能复用优势在稀疏奖励下仍在。核心退回分层技能复用，自动机只是调度表示，收缩"为什么要自动机"的主张。

**No-Go**：压缩、塑形、重解析、技能复用在稀疏奖励下全部无效。说明此前现象依赖稠密进展奖励和特定导航设定，不进入 PPO 或机器人。
