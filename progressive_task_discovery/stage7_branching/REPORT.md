# Stage 7 完成报告：分支任务、历史歧义与技能复用

**本轮完成 Stage 7，包括同地图控制、强历史基线、冻结参数的新种子验证与立即/延迟消融。没有进入反馈噪声、PPO或机器人。** 共6,096组主运行，560,640,000次轻量tabular训练交互；另有128次行为完全一致的诊断回放。开发用12个种子，正式验证与长共享路径测试各用32个新种子；运行数不是独立随机种子数。

结论是：**必须保存足够的历史；立即技能复用的收益在分支任务中保留。但学习到的前缀结构与等价历史字典完全一致，尚未证明一般结构推断或automaton表示具有独立优势。** 相对强手写监控器，长任务中的收益明显小于相对弱计数基线的表面差距。

## 1. 怎么让结构歧义真正影响决策

如果允许agent一直选择同一分支，它可以回避历史记忆问题。因此训练交替使用两个真实起点，评价对两个开局各赋50%权重。每个起点的唯一出口必须穿过自己的A或B事件。两条路线通过实际运动汇合，不传送、不免费跳到frontier。

最终主实验在分叉前插入一个共同事件。例如种子400：

```
A → E → D → E → C → D → C → D
B → E → C → E → C → D → C → D
```

在完成 `A→E` 或 `B→E` 后，两者到达同一物理交叉点J，进度都是2、最后一个成功事件都是E，但下一目标分别为D和C。这同时排除了“进度计数”和“只记最后一个事件”的充分性。后续两条分支合并，故一个合适的监控器可以在适当阶段忘掉最初的cue。

地图为13×13墙格中的28个可行走格，四方向确定性动作，五种准确事件。所有局部目标通过同一个交叉点连接。任务每条分支包含k次进度事件；错误事件忽略，正确进展奖励1，每步成本0.01。技能、任务Q表都从零开始。每条可行路线的最短长度都是 `12k−11`，不同分支、同地图控制与不同共享路径长度保持这一长度关系。

![真实歧义见证](</Users/yuhang/Downloads/why TL/progressive_task_discovery/stage7_branching/figures/ambiguity_witness.png>)

同一个交叉点、同一个计数下，确定性平稳的count策略只能选择同一种外出方向。对下一目标不同的两条历史，它最多完成其中一条。这里的50%上限针对**此地图、此任务和确定性平稳策略类**，不是对所有随机策略、历史策略或一般RL的上限。我们还用精确动态规划评价了已训练count/last-event策略保留epsilon=.05/.2时的成功率，结果保留在CSV；它们在本预算下也没有解决任务。这并不证明任意随机count策略都不可能解决。

## 2. 最重要的因果控制：保留地图，只去掉歧义

同地图控制保留起点、走廊、事件、预算、参数、种子和最短路线长度，只把两条历史的后续目标改为相同。

**Count与last-event基线在同地图无歧义控制中全部达到门槛；在正式有歧义任务中，所有长度/时限组合均为0/32。** 因此不能把失败简单解释为地图太难。手写监控器在无歧义控制中退化为计数器；二者的轨迹和Q表精确一致。

早期“分叉紧接A/B”的版本保留在development目录。那个版本只需记住最后一次成功事件就可能解决，故最终主实验采用更严格的共享事件版本；没有把它与最终结果混合汇总。

## 3. 方法与公平性

所有方法每条真实交互都做6次Bellman更新，alpha=.3、gamma=.98。回放方法为1次在线任务Q更新+5次普通缓存回放；技能方法为1次任务Q更新+5个目标的技能更新。技能模块统一写成 `Q_skill(s,g,a)`，所有技能方法使用相同代码和事件重标记规则。

“完整历史”保留所有收到成功反馈的事件前缀，忽略无进展事件；在已声明的精确反馈/错误事件忽略语义下，这是充分历史。`learned_replay`将同样的前缀在线组织为前缀树并记录正转换。两者的RL可见信息和更新规则相同，因此应当一致。

手写监控器知道这个任务族的分支与合并位置，保留最初cue直到分叉处理完毕；它不知道随机生成的未来目标序列，也不读取环境内部状态。**它是带有结构先验的强控制，不是与未知结构方法信息完全相同的对手。** Oracle额外知道所有目标转换，但技能仍从零学。

立即/延迟方法都训练相同的技能库。延迟方法只有在两种开局都发生过完整任务成功后才可调用；立即方法每确认一条正转换就可调用。正式比较先在开发集分别调优epsilon；另补两者epsilon均为.005的严格时机消融，收益仍保留。

**共享技能代码不等于共享技能数据或共享权重。** 在线策略改变行动，后续采样也会改变。Stage7测得的是调度改变后的整个闭环效果；把技能本身完全固定、排除间接采样收益，是Stage8的任务，本轮没有声称完成。

## 4. 正式新种子结果

主实验使用种子400–431，k=4、8、12，共享事件数1，时限16k和24k；每组100k训练步，每1k步冻结贪心策略，精确评价两个初始条件。由于本设置无随机运动，单个开局的成功率是0或1，均衡成功率是0、.5或1；达到90%意味着两个开局都成功。

## 5. 立即利用的效果是否仍主要来自前缀

在两者都使用epsilon=.005的消融中，k=12：

- H=16k：延迟35,812步，立即10,031步；成本比0.280，95%区间约[0.269,0.291]。
- H=24k：延迟29,719步，立即7,406步；成本比0.249，95%区间约[0.242,0.257]。

两个方法同样每步6次更新；变化是允许部分结构何时影响行动。这里没有声称它们的在线物理轨迹相同。

以主实验H=24k、k=12为例，直到两种开局都至少完整成功一次：延迟方法花在已知前缀上约23,653步、未知frontier约5,594步；立即方法分别约2,041步和4,826步。这里“已知前缀”指已确认下一转换标签，并不意味着该段技能已完全可靠。减少的是反复执行这些已知段的成本，未知探索成本变化较小。严格同epsilon消融的分解也已画在下图。

![同地图和时机控制](</Users/yuhang/Downloads/why TL/progressive_task_discovery/stage7_branching/figures/causal_controls.png>)

另用种子500–531，把cue与关键决策之间拉开三个共享事件，保留冻结参数。k=12时，立即复用8,375步，手写监控器11,500步、完整历史回放17,656步、延迟复用31,531步。立即/手写的成本比0.728，区间约[0.697,0.761]。收益没有因为最初cue变得更久远而消失。

## 6. 结构和技能指标应该怎么读

关键交叉点的task-state可区分准确率，通过对任意feature ID做最优语义对齐后计算：count、last-event为50%，完整历史、前缀树及手写监控器为100%。它衡量表示是否合并了需要区分的历史，**不是一般结构推断能力或最小自动机学习准确率**。

在k=12、一个共享事件时，前缀树有23个非终止历史状态，手写/参考任务状态有14个；前缀树尚未自动识别两条路径合并后的等价后缀。Last-event方法也恰有14个feature状态，但它在关键位置仍然错误合并两条历史；状态数量相等不意味着语义正确。

技能方法最终next-goal覆盖与准确率为100%，实际错误绑定为0。这里反馈完全准确，且只记录被反馈确认的正转换；因此这**不能支持H3的confidence-aware主张**。没有噪声下的错误假设，也没有运行置信度调度。结构修订数0同样来自当前保守前缀树的实现，而不是证据显示算法能正确处理结构冲突。

记录包括：成功率AUC、first/stable90、两分支成功、已知/未知交互、语义对齐准确率、下一目标覆盖、错误绑定、转换首次发现时间、技能尝试/目标成功/其他进度打断/超时，以及结构修订数。回放策略不直接输出g，故其next-goal与wrong-binding指标在汇总表留空。原始JSON中的被动转换缓存诊断不能当成其动作策略的目标预测。

为避免把其他正确进度造成的技能中断算成技能失败，`skill_other_progress`单列。例如根状态调用A技能时，先经过B并产生合法进展，就应切换任务阶段。在128次主实验诊断复跑中，按 `(已观察前缀, g)` 保存了尝试、命中、其他进度、超时和错误绑定次数，并确认行为哈希与原运行一致。见 [skill_context_diagnostics.jsonl](</Users/yuhang/Downloads/why TL/progressive_task_discovery/stage7_branching/results/skill_context_diagnostics.jsonl>)。这些只覆盖静态动力学，不能作为Stage10中context-safe复用的证据。

## 7. 对H1、H2、H3的判断

| 假设 | 本轮结论 |
| --- | --- |
| H1：count不足时task state有价值 | 支持“必须区分历史”的版本；完整历史同样足够，尚不支持automaton或学习压缩结构优于等价手写历史表示 |
| H2：部分结构立即利用减少prefix cost | 支持：在分支任务、新种子、相同更新数、相同epsilon消融中保留；相对强手写监控器的收益有长度与时限条件 |
| H3：结构不确定时confidence-aware更好 | 未测试；反馈无噪声、错误绑定为0，不能据此判断 |

**Stage7通过了继续进入Stage8的机制门槛。** 它没有满足“结构推断创新已被证明”的门槛，也尚未到Stage9的Go/Weak Go判断。当前证据最接近“历史条件下的任务进度识别 + 立即调用共享技能”。

下一步的具体设计已写入 [NEXT_STAGE8.md](</Users/yuhang/Downloads/why TL/progressive_task_discovery/stage7_branching/docs/NEXT_STAGE8.md>)：先固定所有方法使用的技能库，区分直接调用收益与策略改变采样后技能变强的间接收益。随后才在Stage9引入噪声，同时处理任务状态信念和转换置信度，不能直接把带噪progress计数当成真状态。

本轮仍使用固定五种事件，长任务有大量技能重复，没有回答horizon与重复率的独立作用。这个因素分解、ISA/JIRP复现、噪声、context-dependent skills、PPO和机器人均未在本轮执行，不应从当前结果外推。
