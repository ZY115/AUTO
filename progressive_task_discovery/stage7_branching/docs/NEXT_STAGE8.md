# Stage 8 具体设计：固定技能库，拆分调度的直接与间接作用

状态：设计已写，未执行。当前请求优先完成Stage7；本文件不表示Stage8–10已经验证。

## 当前因果问题

Stage7的立即和延迟方法使用同一技能算法与更新预算，但行动会改变采样，技能权重随后也会不同。当前测得的是整个闭环的总效果。不能一面让多个online策略自由行动，一面声称它们收到完全相同的环境数据。

## 8A：同一物理数据、同一技能权重

1. 在当前分支地图中用一个预先固定的行为策略采集物理交互数据，保留所有移动成本与失败；没有示范或传送。
2. 所有条件使用同一份数据、同一顺序、同一个初始化，从零训练 `Q_skill(s,g,a)`。检查权重哈希完全一致。数据采集成本计入每个方法的总样本账，不视为免费预训练。
3. 冻结技能库。立即、延迟、历史字典和oracle只改变何时/调用哪个g；online阶段不得改变技能Q值。
4. 所有方法的任务层继续使用相同数量的更新；物理轨迹允许因决策而不同。这正是要测的调度效果。不能把online数据称为相同。
5. 配对比较：相同累计物理交互预算、first/stable90、AUC、prefix/frontier、错误绑定、固定技能的实际成功率。另保留Stage7的joint-online版本，测技能再学习带来的增量。

主比较采用同一epsilon，方法独立调参只作为附加敏感性分析。配置在开发种子上冻结后换新种子确认。

## 8B：对结构学习器使用同一事件数据

另做离线回放诊断：所有结构学习器按相同顺序消费一组带反馈的事件轨迹，在相同数据量处比较可用转换、状态区分、目标预测与绑定决定。这个实验隔离表示/结构学习差异，但不声称能测闭环探索的总效果。

## 进入Stage9的条件

固定技能库后，立即利用若仍降低前缀成本，则结构调度具有直接价值。若收益大幅消失，应把主因改写为调度改变采样后，局部技能学得更快。

引入假阳性/假阴性时需要区分：真实任务是否推进、agent收到了什么反馈、agent认为自己处于哪个task state。简单累计带噪progress会同时破坏状态定位和候选边统计。先设计状态belief与噪声观测模型，再比较hard/delayed/confidence-aware，避免在错误q上累计N+/N-后误把结果当成正确转换置信度。H3不能用本轮零错误绑定的数据预先断言。

horizon与事件/技能重复率分解仍需单独设计更多事件的地图，并保持路径长度、可达性和物理难度可比较；扩大事件数本身也会改变技能预学习成本。
