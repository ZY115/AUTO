# 排错与已知的坑

## 排查顺序

`verify.py` 哪一项失败，就从那一项开始：

| 失败项 | 先查什么 |
|---|---|
| 1 | `HRM_LEARNING` 环境变量有没有设、路径对不对 |
| 2 | 三个上游仓库的提交号对不对；`gym` 是不是被别的包升级了 |
| 3 | 补丁 01 有没有应用（`git -C <envs仓库> diff --stat` 应该看到一个文件被改） |
| 4 或 6 | `src/` 里的两个文件有没有复制到 `hrm-learning/src/reinforcement_learning/`；补丁 02 有没有应用 |
| 5 | 复制进去的文件是不是空的或者过期的 |
| 7 | `nvidia-smi` 能不能看到卡；torch 是不是装成了 CPU 版 |

其他症状：

- **跑得比预期慢几十倍** → 大概率是 `er_start_size`，见 [EXPERIMENTS.md 的陷阱一](EXPERIMENTS.md#两个会让你估错的陷阱)
- **结果全是 0** → 先确认幕数够不够。10,000 幕时岩浆条件本来就全是 0，这是正常的
- **`run_grid.py` 说全部跳过** → 输出文件里已经有这些运行了，换个 `--out` 或删掉旧文件

## 已知的坑

### 1. `four_rooms` 的尺寸走 `size` 键

不是 `width` / `height`，而且必须是 **≥ 11 的奇数**。只给 `width` / `height` 会报
`The grid for four rooms must be at least 11x11`。`run_grid.py` 已经处理了。

### 2. `max_objs_per_class: 2` 是上限不是定值

生成器在 1 到 2 之间随机。**不能假设每类恰好两个物体。**
做任何「两个实例是否相同」的比较时，要逐项比对实际生成的坐标，不能只看配置。

### 3. `state_format` 会改变算法路由

`full_obs` 下 `ihsa-hrl` 走的是 **DQN 版**，不是表格版。两者是不同的实现，
**别混着比**。`run_grid.py` 会把 `state_format` 写进每一行结果，
`analyze_grid.py` 也会按它分组。

### 4. 神经版 Y10 默认共享回放缓冲

只有网络参数是分开的，回放缓冲是共用的。**这是故意的。**

原因：`er_start_size = 100000`。如果连缓冲也按阶段分开，一个只占五分之一访问量的阶段
要五十万步才开始学，访问更少的阶段可能永远开不了学——那样 Y10 会因为一个记账阈值而输，
不是因为它不能共享。共享缓冲让两臂看到同样的数据和同样的启动阈值，
**只隔离「参数是否共享」这一个因素**，这是这条臂最强的公平形式。

想看字面读法（连缓冲也分开）：在配置里加 `perstate_split_buffer: true`。
两种都可以报，但要在报告里说清用的是哪一种。

### 5. 不要擅自加步进惩罚

作者配置的 `pseudoreward_after_step = 0.0`。我们早期自己加过 −0.01，
让一个对照方法看起来完全崩溃；去掉之后它反超。这是**同一个项目里第二次**
被步进惩罚坑到。要研究这个因素就用 `--protocols author,stepcost` 显式对照。

### 6. 输出目录要指到仓库外

配置里的 `folder_name` 和 `checkpoint_folder` 如果指向 git 检出，
训练产物会写进仓库里。`run_grid.py` 用 `--work` 参数控制，默认 `/tmp/hrm_grid`。
建议指到一块大盘：`--work /scratch/hrm`。

一次 36 运行的网格会产生几百兆的中间文件。真正要保留的只有 `--out` 那个 `.jsonl`。

### 7. 不需要装 ILASP

我们跑的是 `training_mode: handcrafted`，任务结构是给定的，不是学出来的。
启动器仍然会调用 ILASP 的环境变量设置函数，补丁 02 修的就是这个调用在 Python 3.10 上的崩溃。
**不需要下载或编译 ILASP。**

### 8. 上游仓库如果有更新

以 `README.md` 里锁定的提交号为准。补丁是针对那些提交生成的，
上游变动后可能应用失败。真要升级，先确认 `verify.py` 第 4 和第 6 项仍然通过。
